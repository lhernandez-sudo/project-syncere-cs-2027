# Week 6: Dictionaries and Friendly Classes Review

This is the final foundations review before students begin the December capstone. The instructor is absent, so the session is fully self-guided through Google Colab. Students learn dictionaries from the beginning, practice simple classes, and finish with a guided investigation of controversies connected to common technology products.

## Learning objectives

By 1:00 PM, students can:

- Create, read, update, and safely access dictionary values.
- Loop through dictionary keys and values.
- Select a dictionary for one structured record or a class for many objects with shared behavior.
- Define a simple class with `__init__`, attributes, and methods.
- Create two independent objects from the same class.
- Use embedded checks to locate syntax and functionality problems.
- Explain how one common technology company earns revenue.
- Distinguish a legal allegation, court ruling, and settlement.
- Support a position with evidence from a reliable source.

## Work style

Students complete the programming block independently. For the technology investigation, students form groups of 2 or 3 and may divide research and speaking in any way that feels comfortable.

- Try each challenge independently first.
- Predict the result before pressing Run.
- Read the failed check before changing code.
- After one repair attempt, students may quietly compare with a neighbor.
- Sharing an icebreaker identity is optional.
- Group members discuss evidence, but the final exit ticket is individual.

## Key vocabulary

- **Dictionary:** A collection of key-value pairs.
- **Key:** The label used to find a dictionary value.
- **Value:** The data stored under a key.
- **Class:** A blueprint for objects that share attributes and methods.
- **Object:** One instance created from a class.
- **Attribute:** A value stored on an object.
- **Method:** A function defined inside a class.
- **`__init__`:** The method that sets an object's starting state.
- **`self`:** The current object receiving a method call.

## Self-guided lesson sequence

There is no live lesson this week. Each notebook follows the same routine:

1. Read the concept explanation.
2. Predict the example output.
3. Run the working example.
4. Run the starter challenge once.
5. Read every failed integrity check.
6. Repair one small part at a time.
7. Rerun until every check passes.

Syntax errors must be fixed before a cell can reach its checks. Functionality checks use several inputs so a single hard-coded answer will not pass.

## Guided exercises

Notebook 1 assumes students have never seen dictionaries and begins with reading, changing, and adding one value at a time. Notebook 2 then builds simple `Character` and `PowerUp` classes. The Tech Investigation guides groups through business models, lawsuits, and social questions involving TikTok, Google, Meta, Amazon, Apple, and generative AI. Notebook 3 remains archived in the folder but is not part of this class plan.

## Challenge artifact

Every student should complete the first two dictionary practices, at least one dictionary challenge, and the guided sections of Notebook 2. The final class boss is a stretch goal if time permits.

## Technology investigation

At 11:30, students form groups of 2 or 3 and choose one of six technology topics. Each topic begins with a readable Associated Press, PBS NewsHour, or Reuters article. Government filings, court materials, and company statements remain available as optional deeper sources. Students explain how the product makes money, identify the controversy, separate established facts from allegations, and prepare a two-minute share-out. Students do not need personal accounts and should not share private experiences or login information.

## Exit ticket

1. Which business model surprised you most?
2. What is one fact you can verify with a reliable source?
3. What question do you still have?
4. What should engineers consider besides whether a product works?
