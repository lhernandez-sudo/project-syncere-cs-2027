# Final AI Capstone

Build a complete Python application that uses AI as one component of a solution to a real user need. A generic chatbot is not enough: the project must have a specific purpose, defined success criteria, and evidence that its AI output was evaluated.

## Development stages

1. **Problem selection:** Identify the user, need, and reason AI may be appropriate.
2. **Responsible-use review:** Consider privacy, bias, safety, copyright, access, and possible misuse.
3. **Project proposal:** Define requirements, non-goals, success criteria, and evaluation cases.
4. **Prototype:** Prove that the riskiest technical feature can work.
5. **Build:** Develop the application in small, testable pieces.
6. **Evaluate:** Test conventional code and assess AI output against the stated criteria.
7. **Improve:** Respond to failures and peer feedback with documented changes.
8. **Present:** Demonstrate the final product and explain its limitations.

## Required evidence

- A clear user and problem statement
- A working Python application
- A README with setup, usage, design decisions, and limitations
- No secrets or API keys committed to GitHub
- Tests for deterministic Python code
- A documented set of AI evaluation cases
- Safeguards for important failure modes
- Meaningful commits, issues, and project milestones
- Disclosure of AI assistance used during development
- A live demonstration and individual reflection

## Possible directions

- Study-material generator with accuracy checks
- Community-resource navigator
- Career-preparation assistant
- Reading-level adaptation tool
- Youth-program feedback analyzer
- Local-history or oral-history exploration tool

## Rubric

| Category | Weight | Evidence |
| --- | ---: | --- |
| Problem definition and user value | 15% | The project addresses a specific, meaningful need. |
| Python and application quality | 20% | The application is organized, reliable, and usable. |
| AI integration | 15% | AI is necessary to the chosen feature and integrated intentionally. |
| Evaluation and safeguards | 20% | Test cases reveal strengths, failures, limitations, and mitigations. |
| Responsible use | 10% | Privacy, bias, safety, attribution, and misuse are considered. |
| GitHub and documentation | 10% | Project history and documentation make the work understandable. |
| Demonstration and reflection | 10% | The student explains decisions, evidence, limitations, and future work. |
