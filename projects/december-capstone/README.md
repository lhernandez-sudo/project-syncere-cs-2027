# December Capstone

Build a useful Python program that addresses a clearly defined problem for a real or realistic user.

## Schedule

### Saturday 1 - Plan

- Identify the user and problem.
- Research requirements and existing approaches.
- Define inputs, processing, and outputs.
- Write pseudocode or create a flowchart.
- Break the project into GitHub issues.

### Saturday 2 - Build and test

- Implement the smallest working version.
- Validate user input and handle common errors.
- Test important behavior.
- Ask a classmate to use the program and record feedback.

### Saturday 3 - Improve and present

- Resolve important bugs and usability problems.
- Improve the README and code comments.
- Rehearse a short demonstration.
- Present the program and reflect on the process.

## Required evidence

- A working Python program
- A README explaining the user, problem, setup, and usage
- Pseudocode or a flowchart
- Meaningful tests
- A Git history showing progress over time
- A short live demonstration
- An individual reflection

## Suggested projects

- Personal budget assistant
- Study planner
- Volunteer-hours tracker
- Community-resource directory
- Text-based educational game
- Survey or school-data analyzer

## Rubric

| Category | Weight | Evidence |
| --- | ---: | --- |
| Problem and user | 15% | The need and intended user are specific and credible. |
| Program behavior | 25% | The required features work and errors are handled appropriately. |
| Code quality | 15% | The code is readable, organized, and uses functions effectively. |
| Testing and improvement | 15% | Tests and peer feedback lead to documented revisions. |
| GitHub and documentation | 15% | Commits show progress and the README supports a new user. |
| Demonstration and reflection | 15% | The student explains the product, decisions, challenges, and next steps. |
